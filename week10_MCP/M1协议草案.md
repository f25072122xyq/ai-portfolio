# M1 会话协议草案

本草案基于本周已跑通的 `hsk_mcp_server.py`（服务端）与 `demo_client.py`（客户端）的真实交互逻辑推演而成，用于规范未来的多端通信。

## ① 事件类型与字段
在多端通信中，每一次通信都必须包含标准化的字段：
- **基础字段**：`session_id`（当前会话的唯一标识）、`seq`（序列号，从1开始自增，用于保证顺序）、`ts`（时间戳）、`type`（事件类型）、`payload`（具体数据，如 JSON 格式）。
- **真实事件类型推演**：
  1. `client_request`：客户端发起请求（例如在 demo_client.py 中发起 `list_tools()`）。
  2. `server_response`：服务端返回结果（例如返回了 `['hsk_level', 'list_by_level']`）。
  3. `tool_call`：客户端要求执行工具（如 `call_tool("hsk_level", {"word": "把"})`）。
  4. `tool_result`：服务端返回工具执行结果（如返回 `把 -> 3 级`）。
  5. `error`：异常抛出（如我们之前捕获的 `TaskGroup` 异步报错）。

## ② 状态机 (State Machine)
基于本次实验的 stdio 通信过程，状态机流转如下：
- **`idle` (空闲)**：客户端未启动。
- **`connecting` (连接中)**：客户端通过 `stdio_client` 启动服务端进程并尝试握手。
- **`listening` (监听/等待)**：服务端启动后挂起（即 `mcp.run()` 的状态），等待客户端指令。
- **`processing` (处理中)**：服务端接收到 `tool_call` 并执行 `hsk_level` 等函数。
- **`disconnected` (断开)**：测试完成，连接关闭。
- **打断回退机制**：若在处理中（`processing`），客户端强行中断（如用户 `Ctrl+C`），服务端应立即终止当前任务，清理未释放的异步资源，退回 `listening` 状态等待新连接。

## ③ 权威与幂等 (Authority & Idempotency)
- **唯一权威**：服务端（`hsk_mcp_server.py`）是唯一的数据权威。客户端不能自己猜测 HSK 等级，必须通过服务端去读取 `VOCAB_DATA`。
- **幂等性**：为了防止网络波动导致客户端重复发送同一个 `tool_call`，服务端必须维护一个已执行的 `seq` 集合。同一个 `seq` 的请求，无论发多少次，服务端都只返回第一次的结果，不重复执行计算。

## ④ 断线语义 (Disconnection Semantics)
- 客户端断线重连后，必须在 payload 中携带 `last_received_seq`。
- 服务端收到重连请求后，检查自己的历史事件池。如果发现 `last_received_seq` 落后于当前最新 `seq`，服务端会自动把中间丢失的 `tool_result` 或 `error` 事件按顺序补发给客户端，确保多端状态最终一致。
